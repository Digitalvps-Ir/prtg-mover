# PRTG Mover — راهنمای فارسی

ابزاری برای **بکاپ، انتقال و بازگردانی کامل سرور PRTG** به همراه **VPNهای ویندوز** و **فایل‌های دسکتاپ**، از یک سیستم مدیر (Manager) و با داشبورد تحت وب.

[English README](README.md) · [تغییرات نسخه‌ها](CHANGELOG.md) · [رفع مشکل](docs/TROUBLESHOOTING.md)

## این ابزار چه کار می‌کند؟

۱. **اول بررسی می‌کند.** دسترسی، مجوز ادمین، فضای دیسک و نسخهٔ PRTG روی همهٔ سرورها چک می‌شود. اگر مشکلی باشد، به هیچ سروری دست زده نمی‌شود.

۲. **بدون دست زدن به مبدأ کپی می‌گیرد.** PRTG روی مبدأ روشن می‌ماند. فایل‌ها از روی Snapshot ویندوز (VSS) خوانده می‌شوند و مبدأ به فضای خالی دیسک نیاز ندارد.

۳. **یک فایل بکاپ روی Manager نگه می‌دارد.** هر بکاپ یک فایل `.zip` با manifest و هش SHA-256 است و از داشبورد قابل دانلود است.

۴. **روی مقصد بازگردانی می‌کند.** اگر PRTG نصب نباشد، خودِ برنامه از مبدأ کلون می‌شود و به فایل نصبی نیازی نیست.

۵. **PRTG را اجرا و سلامتش را ثابت می‌کند.** کار فقط وقتی موفق اعلام می‌شود که سرویس Core و Probe هر دو Running باشند، وب‌اینترفیس جواب بدهد و بعد از ۴۵ ثانیه هم پایدار بماند.

کارهای ناموفق یا قطع‌شده با دکمهٔ **Resume** ادامه پیدا می‌کنند و مراحل انجام‌شده تکرار نمی‌شوند.

روی سرورها هیچ نرم‌افزاری نصب نمی‌شود.

## روش اتصال: RDP یا WinRM

برای هر سرور **یکی** از این دو روش انتخاب می‌شود (Servers ← Edit ← Connection method):

| | **RDP (پیش‌فرض)** | **WinRM** |
|---|---|---|
| پیش‌نیاز روی سرور | هیچ؛ فقط دسترسی ریموت دسکتاپ | فعال بودن WinRM |
| تغییر روی سرور | هیچ | سرویس WinRM و یک قانون فایروال |
| روش کار | دکمهٔ RDP ریموت دسکتاپ را باز می‌کند. یک دستور را در PowerShell با دسترسی Administrator روی سرور Paste می‌کنید. | کاملاً خودکار |
| در طول کار | پنجرهٔ RDP باید باز بماند (Minimize مشکلی ندارد) | چیزی لازم نیست |
| انتقال فایل | از طریق درایو وصل‌شده در RDP | فشرده، با چند رشتهٔ موازی، قابل ادامه بعد از قطعی |
| مناسب برای | سرورهایی که نباید تنظیمشان عوض شود | اجرای بدون حضور، بکاپ زمان‌بندی‌شده، دیتای حجیم |

**تست:**
- هر سرور دو دکمهٔ جدا دارد: **Test RDP** و **Test WinRM**.
- دکمهٔ **Test all** هر دو را امتحان می‌کند. اگر حداقل یکی موفق باشد، نتیجه **PASS** است.

## پیش‌نیازها

- **Manager:** ویندوز ۱۰/۱۱ یا Windows Server با PowerShell 5.1، و فضای خالی حدود **۲.۲ برابر حجم دیتای PRTG**.
- **سرور مبدأ:** Windows Server 2012 R2 تا 2025 و یک اکانت Administrator. به فضای خالی نیاز ندارد.
- **سرور مقصد:** همان، با فضای خالی حدود **۱.۲ برابر حجم دیتای PRTG**.
- **PRTG:** فقط روی مبدأ لازم است. اگر روی مقصد نصب باشد، نسخه‌اش باید برابر یا جدیدتر از مبدأ باشد.

## نصب و راه‌اندازی

### ۱. نصب روی سیستم Manager

فایل‌ها را بگیرید (با `git clone` یا دانلود ZIP از GitHub و باز کردن آن) و روی **`install.cmd`** دوبار کلیک کنید. همین کار از داخل PowerShell:

</div>

```powershell
git clone https://github.com/Digitalvps-Ir/prtg-mover.git
cd prtg-mover
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

<div dir="rtl">

به دسترسی Administrator نیاز نیست. نصب‌کننده این کارها را انجام می‌دهد:

۱. ویندوز و PowerShell (نسخهٔ 5.1 یا بالاتر) را بررسی می‌کند.
۲. برنامه را در `C:\PrtgMover` کپی می‌کند.
۳. اسکریپت‌ها را Unblock و نصب را تست می‌کند: همهٔ اسکریپت‌ها باید سالم باشند و داشبورد باید جواب بدهد.
۴. میانبر **PRTG Mover** را روی دسکتاپ و در منوی Start می‌سازد.
۵. داشبورد را اجرا می‌کند. مرورگر با آدرس `http://localhost:8765/` باز می‌شود و پنجرهٔ کنسول لاگ زندهٔ همهٔ کارها را نشان می‌دهد.

| گزینه | کاربرد |
|---|---|
| `-InstallPath D:\Tools\PrtgMover` | نصب در پوشهٔ دیگر |
| `-Source <پوشه یا zip>` | نصب از یک پوشه یا فایل ZIP دیگر |
| `-TrustedHosts 10.0.0.10,10.0.0.20` | آماده‌سازی Manager برای سرورهایی که با WinRM ساده (HTTP) وصل می‌شوند. ویندوز برای این مرحله دسترسی Administrator می‌خواهد. |
| `-Port 8080` | پورت داشبورد |
| `-NoShortcut` ، `-NoStart` | میانبر نسازد، داشبورد را اجرا نکند |
| `-Autostart` | داشبورد با ورود شما به ویندوز اجرا شود (کوچک‌شده و بدون باز کردن مرورگر). در به‌روزرسانی حفظ می‌شود. با `-NoAutostart` خاموش می‌شود. |
| `-Uninstall` | حذف میانبرها و فایل‌های برنامهٔ همین نصب |

**باز کردن داشبورد:** از میانبر استفاده کنید. اگر داشبورد از قبل در حال اجرا باشد، میانبر همان را در مرورگر باز می‌کند و نسخهٔ دومی اجرا نمی‌شود.

**به‌روزرسانی یا تعمیر:** فایل‌های جدید را بگیرید و نصب‌کننده را دوباره اجرا کنید. قبلش پنجرهٔ داشبورد را ببندید.

**به دیتای شما دست زده نمی‌شود**، نه در به‌روزرسانی و نه با `-Uninstall`: لیست سرورها (`config\`)، یوزر و پسوردهای ذخیره‌شده، کارها و لاگ‌ها (`data\`)، بکاپ‌ها (`backups\`) و فایل‌های نصب PRTG (`installers\`) سر جایشان می‌مانند.

اگر فقط فایل `install.ps1` را داشته باشید، برنامه را خودش از GitHub دانلود می‌کند. ریپو خصوصی است، پس این کار فقط روی سیستمی جواب می‌دهد که `git` یا GitHub CLI در آن لاگین باشد.

بدون نصب‌کننده هم می‌شود: با `powershell -ExecutionPolicy Bypass -File .\Start-PrtgMover.ps1` یا دوبار کلیک روی `Start-PrtgMover.cmd` داشبورد از همان پوشه اجرا می‌شود.

### ۲. انتخاب روش اتصال

**روش RDP** به هیچ آماده‌سازی نیاز ندارد.

**روش WinRM:** فایل `tools\Enable-PrtgMoverRemoting.ps1` را روی هر سرور کپی کنید و یک بار در PowerShell با دسترسی **Administrator** اجرا کنید:

</div>

```powershell
powershell -ExecutionPolicy Bypass -File .\Enable-PrtgMoverRemoting.ps1 -Https
```

<div dir="rtl">

این اسکریپت:

- WinRM را با HTTPS (پورت 5986) فعال می‌کند.
- فایروال را برای پورت 5986 **فقط برای IP سیستم Manager** باز می‌کند. این IP را از همان اتصال Remote Desktop که با آن وارد سرور شده‌اید برمی‌دارد. با `-ManagerAddress <IP>` می‌شود آن را دستی داد.
- WinRM ساده (پورت 5985) را در فایروال می‌بندد. ویندوز هنگام فعال شدن Remoting این پورت را باز می‌کند. با `-KeepPlainWinRM` باز می‌ماند.
- نتیجه را بررسی می‌کند و می‌نویسد در داشبورد چه چیزی وارد کنید.

در داشبورد، برای این سرور تیک *HTTPS* و *Skip certificate checks* را بزنید. اگر IP سیستم Manager عوض شد، اسکریپت را دوباره اجرا کنید.

## انتقال قدم‌به‌قدم

۱. **Servers ← Add server:** سرور قدیمی را با نقش *Source* و سرور جدید را با نقش *Target* اضافه کنید. یوزر و پسورد ادمین را **خودتان در همین فرم** وارد کنید.

۲. روی **Test all** بزنید. وضعیت هر دو سرور باید `PASS` شود.

۳. فقط در روش RDP: برای هر سرور دکمهٔ **RDP** را بزنید، لاگین کنید و دستور Agent را Paste کنید. پنجره‌های RDP را نبندید.

۴. در صفحهٔ **Backup & Migrate** مبدأ را انتخاب کنید و مقصد را تیک بزنید. کادر *What this job will do* دقیق نشان می‌دهد چه چیزی کپی می‌شود. بعد **Migrate** را بزنید.

۵. پیشرفت و لاگ زنده را در صفحهٔ **Jobs** ببینید.

۶. موارد بخش «بعد از انتقال» را انجام دهید.

برای **فقط بکاپ گرفتن**، هیچ مقصدی را تیک نزنید.

در صفحهٔ **Backup & Migrate**، قبل از شروع، گزینهٔ **How the files move** هست:

- **RDP** یا **WinRM**: فایل‌ها از این کامپیوتر رد می‌شوند.
- **WireGuard**: تانل بین دو سرور ویندوز. فایل‌ها با WinRM به آدرس تانل سرور دیگر می‌روند (`10.66.66.x:5985`) و روی این کامپیوتر ذخیره نمی‌شوند. قبل از کپی یک تست کوتاه سرعت (MB/s) روی همان مسیر ثبت می‌شود. این کامپیوتر فقط فرمان می‌فرستد. باید یک سرور مقصد انتخاب شود و UDP 51820 بین دو آدرس عمومی باز باشد.
- **IPIP**: همان کپی با WinRM روی آدرس تانل، با پروتکل IP-in-IP، روی شبکهٔ جدا `10.66.67.0/24`. پروتکل ۴ باید بین دو آدرس عمومی باز باشد. مسیر پیش‌فرض اینترنت سرورها عوض نمی‌شود.

اگر کاری خطا داد، علت را از لاگ رفع کنید و **Resume** را بزنید.

## گزینه‌های مهم

- **Don't touch the source (پیش‌فرض روشن):** روی مبدأ هیچ سرویسی متوقف نمی‌شود، هیچ چیزی تغییر نمی‌کند و هیچ دیتایی پاک نمی‌شود.
- **Clone the PRTG program:** برنامهٔ PRTG و سرویس‌های ویندوز آن کپی می‌شوند، پس مقصد به فایل نصبی نیاز ندارد.
- **Copy the source license:** لایسنس مبدأ روی مقصد کپی می‌شود. اگر تیک نخورد، مقصد لایسنس خودش را نگه می‌دارد.
- **Historic monitoring data:** دیتای تاریخچه. اگر خاموش باشد، فقط کانفیگ منتقل می‌شود و کار خیلی سریع‌تر است.
- **لاگ‌ها و کپی‌های خودکار قدیمی کانفیگ:** پیش‌فرض خاموش، چون برای انتقال لازم نیستند.
- **Parallel transfer streams:** تعداد رشته‌های موازی در روش WinRM (پیش‌فرض ۴).
- فایل‌های cache و tmp هیچ‌وقت کپی نمی‌شوند.

## چه چیزی منتقل می‌شود؟

- **کل کانفیگ PRTG:** دیوایس‌ها، سنسورها با همهٔ تنظیمات، قالب‌های نوتیفیکیشن، تریگرها، وابستگی‌ها، زمان‌بندی‌ها، کاربرها و گروه‌ها، مپ‌ها، ریپورت‌ها و تنظیمات SMTP.
- **دیتای تاریخچه** (اختیاری).
- **برنامهٔ PRTG و سرویس‌ها، رجیستری و لایسنس.**
- **موارد سفارشی:** سنسورهای سفارشی، اسکریپت‌های نوتیفیکیشن، lookupها، MIBها و گواهی SSL.
- **آدرس وب‌سرور PRTG:** اگر وب‌سرور به IP سرور قدیمی بسته شده باشد، به IP سرور جدید تغییر می‌کند.
- **VPNهای ویندوز:** در مقصد ادغام می‌شوند و VPNهای موجود بازنویسی نمی‌شوند.
- **فایل‌های دسکتاپ همهٔ کاربران،** مثل فایل‌های `.bat` و VPN.
- **مسیرهای اضافه** که خودتان مشخص می‌کنید.

## صفحه‌های داشبورد

- **Servers:** لیست سرورها، روش اتصال، وضعیت پورت‌ها، Agent، نسخهٔ PRTG و **وضعیت لایسنس**. دکمه‌ها: RDP، Test RDP و Test WinRM.
- **Backup & Migrate:** انتخاب مبدأ، مقصد و گزینه‌ها.
- **Backups:** انبار فایل‌های بکاپ روی Manager. می‌توانید بکاپ را دانلود کنید، روی یک یا چند سرور برگردانید، بکاپ دیگری آپلود کنید یا حذفش کنید.
- **Jobs:** مراحل کار، پیشرفت، لاگ زنده، Resume و دانلود لاگ.
- **Logs & Audit:** همهٔ کارهای انجام‌شده، لاگ Manager و دکمهٔ **Download diagnostics** (یک فایل zip از همهٔ لاگ‌ها، بدون پسورد).

دکمهٔ **Make PRTG reachable** فقط وقتی نمایش داده می‌شود که تست نشان بدهد PRTG یک سرور فقط روی `127.0.0.1` جواب می‌دهد. این دکمه وب‌سرور را به IP خود سرور وصل می‌کند و PRTG را روی آن ری‌استارت می‌کند. در انتقال‌های جدید این کار خودکار انجام می‌شود.

```powershell
.\cli\Invoke-PrtgMover.ps1 -Action Restore    -BackupName PRTG_OLD_20260928-221500.zip -Target PRTG-NEW
.\cli\Invoke-PrtgMover.ps1 -Action FixBinding -Target PRTG-NEW
```

## بعد از انتقال

- **دو PRTG همزمان:** چون مبدأ روشن می‌ماند، تا وقتی PRTG قدیمی را خاموش نکنید هر دو مانیتور می‌کنند و نوتیفیکیشن می‌فرستند.
- **فعال‌سازی لایسنس:** PRTG لایسنس را به سخت‌افزار همان سروری که رویش فعال شده قفل می‌کند. کلید لایسنس کپی می‌شود، ولی روی سرور جدید PRTG پیغام `No License (System Changed)` می‌دهد و تا وقتی لایسنس آن‌جا فعال نشود سنسورها را متوقف می‌کند (Setup ← License Information، یا از طریق Paessler). ابزار این وضعیت و آخرین خطای فعال‌سازی را نشان می‌دهد، ولی لایسنس فعال نمی‌کند و به لایسنس سرور مبدأ دست نمی‌زند.
- **استفاده از لایسنس:** طبق شرایط لایسنس خودتان ببینید چند سرور همزمان مجاز است، و بعد از تأیید سرور جدید، PRTG قدیمی را خاموش کنید.
- **دستگاه‌هایی که فقط IP قدیم را قبول می‌کنند:** اگر دسترسی SNMP یا WMI روی دستگاه‌ها به IP سرور قدیمی محدود است، IP جدید را هم مجاز کنید.
- **Remote Probeها:** اگر IP سرور جدید فرق می‌کند، آدرس Core را در تنظیمات هر Probe اصلاح کنید.
- **پسوردهای VPN:** ویندوز اجازهٔ انتقالشان را نمی‌دهد. یک بار روی سرور جدید وارد کنید.
- **ساعت Manager:** اگر ساعت این سیستم عقب باشد، گواهی HTTPS تازهٔ WinRM نامعتبر دیده می‌شود. ابزار صبر می‌کند تا معتبر شود؛ با Sync کردن ساعت، انتظار تمام می‌شود.

## امنیت

- پسوردها هرگز به‌صورت متن ساده ذخیره نمی‌شوند (رمزنگاری DPAPI ویندوز).
- داشبورد به‌طور پیش‌فرض فقط روی `localhost` در دسترس است و هیچ محافظت دسترسی ندارد: نه توکن دارد و نه بررسی می‌کند درخواست از کجا آمده است. هر برنامه روی سیستم Manager و هر صفحهٔ وبی که در مرورگر همان سیستم باز باشد می‌تواند به داشبورد دستور بدهد. با `-ListenAll` هر کسی که به پورت دسترسی دارد هم می‌تواند. داشبورد را فقط وقتی لازم دارید اجرا کنید.
- WinRM را فقط برای IP سیستم Manager باز کنید و از HTTPS استفاده کنید. بعد از انتقال می‌توانید آن را دوباره ببندید.
- فایل‌های بکاپ حاوی اطلاعات حساس هستند (کانفیگ PRTG، لایسنس و کلید خصوصی SSL).
- پوشه‌های `backups/` و `data/` و فایل `config/servers.json` هرگز نباید در گیت کامیت شوند. در `.gitignore` قرار دارند.
