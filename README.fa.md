# PRTG Mover — راهنمای فارسی

ابزاری برای **بکاپ، انتقال و بازگردانی کامل سرور PRTG** (کانفیگ، دیتابیس تاریخچه، رجیستری، گواهی SSL و سنسورهای سفارشی) به همراه **VPNهای ویندوز** و **فایل‌های روی دسکتاپ**، از یک سیستم مدیر (Manager) و با داشبورد تحت وب.

[English README](README.md)

## این ابزار چه کار می‌کند؟

۱. سرویس‌های PRTG را روی سرور مبدأ به‌صورت امن متوقف می‌کند تا کانفیگ کامل روی دیسک نوشته شود.

۲. همهٔ این موارد را در یک فایل `.zip` بسته‌بندی می‌کند، همراه با manifest و هش SHA-256:
- پوشهٔ دیتای PRTG
- رجیستری Paessler (شامل لایسنس)
- پوشه‌های سفارشی برنامه (`Custom Sensors`، `Notifications`، `lookups\custom`، `MIB`، `cert`، …)
- VPNهای ویندوز
- دسکتاپ همهٔ کاربران
- مسیرهای اضافه‌ای که خودتان مشخص می‌کنید

۳. بکاپ را روی سیستم Manager نگه می‌دارد و **از داشبورد قابل دانلود** است.

۴. بکاپ را روی یک یا چند سرور مقصد بازگردانی می‌کند:
- اگر PRTG نصب نباشد، آن را بی‌صدا نصب می‌کند.
- از دیتای فعلی مقصد نسخهٔ Rollback نگه می‌دارد.
- همه‌چیز را برمی‌گرداند و **PRTG را خودکار اجرا می‌کند**.

۵. صبر می‌کند تا **وب‌اینترفیس PRTG روی مقصد بالا بیاید** و فقط بعد از آن کار را موفق اعلام می‌کند.

روی سرورها هیچ نرم‌افزاری نصب نمی‌شود. فقط WinRM (PowerShell Remoting) باید فعال باشد.

## پیش‌نیازها

- **Manager**: ویندوز ۱۰/۱۱ یا Windows Server، با PowerShell 5.1 و دسترسی شبکه به سرورها روی پورت 5985 (یا 5986 برای HTTPS).
- **سرورهای مبدأ و مقصد**:
  - Windows Server 2012 R2 تا 2025
  - یک اکانت Administrator
  - فضای خالی دیسک تقریباً **دو برابر حجم دیتای PRTG**
- **نسخهٔ PRTG** روی مقصد باید برابر یا جدیدتر از مبدأ باشد. اگر PRTG روی مقصد نصب نیست، فایل نصبی را در داشبورد آپلود کنید.

## نصب و راه‌اندازی

### ۱. دریافت ابزار روی سیستم Manager

</div>

```powershell
git clone https://github.com/Digitalvps-Ir/prtg-mover.git C:\PrtgMover
cd C:\PrtgMover
```

<div dir="rtl">

### ۲. آماده‌سازی هر سرور مبدأ و مقصد (یک بار)

با RDP به سرور وصل شوید، فایل `tools\Enable-PrtgMoverRemoting.ps1` را روی آن کپی کنید و در PowerShell با دسترسی **Administrator** اجرا کنید:

</div>

```powershell
powershell -ExecutionPolicy Bypass -File .\Enable-PrtgMoverRemoting.ps1 -ManagerAddress <IP-Manager> -Https
```

<div dir="rtl">

این اسکریپت:
- WinRM را فعال می‌کند.
- اجازهٔ مدیریت ریموت با اکانت لوکال را می‌دهد.
- فایروال را **فقط برای IP سیستم Manager** باز می‌کند.
- با سوییچ `-Https`، لیسنر HTTPS هم روی پورت 5986 می‌سازد.

⚠️ **اگر سرورها IP عمومی دارند، حتماً از `-Https` و `-ManagerAddress` استفاده کنید.**

### ۳. آماده‌سازی Manager (یک بار، با دسترسی Administrator)

</div>

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Setup-Manager.ps1 -TrustedHosts <IP-مبدأ>,<IP-مقصد>
```

<div dir="rtl">

### ۴. اجرای داشبورد

</div>

```powershell
powershell -ExecutionPolicy Bypass -File .\Start-PrtgMover.ps1
```

<div dir="rtl">

یا روی `Start-PrtgMover.cmd` دوبار کلیک کنید. مرورگر با آدرس `http://localhost:8765/?token=…` باز می‌شود.

## انتقال قدم‌به‌قدم

۱. **Servers → Add server**:
- سرور قدیمی را با نقش *Source* اضافه کنید.
- سرور جدید را با نقش *Target* اضافه کنید.
- برای هر کدام، یوزر ادمین (مثلاً `Administrator`) و پسورد را **خودتان در همین فرم** وارد کنید. پسورد با DPAPI رمز می‌شود و فقط روی همین سیستم و برای همین کاربر ویندوز قابل استفاده است.

۲. روی **Test all** بزنید:
- وضعیت هر دو سرور باید `ok` شود.
- برای مبدأ، نسخهٔ PRTG و حجم دیتا نمایش داده می‌شود.

۳. اگر PRTG روی مقصد نصب نیست: در صفحهٔ **Backup & Migrate** فایل نصبی PRTG را آپلود کنید (**همان نسخهٔ مبدأ**).

۴. در صفحهٔ **Backup & Migrate**:
- سرور مبدأ را انتخاب کنید.
- سرور یا سرورهای مقصد را تیک بزنید.
- گزینهٔ *Keep stopped* را نگه دارید.
- دکمهٔ **Migrate** را بزنید.

۵. پیشرفت و لاگ زنده را در صفحهٔ **Jobs** ببینید. در پایان، برای هر مقصد وضعیت `PRTG ok` و آدرس وب‌اینترفیس نمایش داده می‌شود.

۶. فایل بکاپ در صفحهٔ **Backups** با دکمهٔ **Download** قابل دانلود است.

برای **فقط بکاپ گرفتن**، هیچ مقصدی را تیک نزنید. در این حالت PRTG مبدأ بعد از بکاپ دوباره اجرا می‌شود.

## روش اتصال: RDP یا WinRM

برای هر سرور **یکی** از این دو روش انتخاب می‌شود (Servers ← Edit ← Connection method):

- **RDP (پیش‌فرض):**
  - روی سرور **هیچ تنظیمی لازم نیست**؛ فقط دسترسی ریموت دسکتاپ کافی است.
  - دکمهٔ **RDP** ریموت دسکتاپ را باز می‌کند و درایو همین سیستم را به سرور وصل می‌کند.
  - یک دستور در کلیپ‌بورد کپی می‌شود. روی سرور PowerShell را با Run as Administrator باز کنید و آن را Paste کنید.
  - بعد از آن، «Agent» کارها را از داشبورد دریافت و اجرا می‌کند.
  - فایل‌ها از طریق درایو وصل‌شده منتقل می‌شوند.
- **WinRM:** کاملاً خودکار است، ولی باید روی سرور فعال باشد.

**تست:**
- هر سرور دو دکمهٔ جدا دارد: **Test RDP** و **Test WinRM**.
- دکمهٔ **Test all** هر دو را امتحان می‌کند. اگر حداقل یکی موفق باشد، نتیجه **PASS** نمایش داده می‌شود.

## بخش Backups برای چیست؟

انبار فایل‌های بکاپ روی همین سیستم Manager است. هر بار که بکاپ یا انتقال انجام می‌شود، یک فایل zip ساخته می‌شود که شامل PRTG، VPN، دسکتاپ و manifest است. این فایل این‌جا نگه داشته می‌شود. در این صفحه می‌توانید:
- **Download:** یک نسخهٔ آفلاین از کل PRTG را دانلود کنید.
- **Restore:** همان بکاپ را هر وقت خواستید روی یک یا چند سرور برگردانید؛ مثلاً برای برگشت به حالت قبل یا ساختن سرور جدید.
- **Upload:** بکاپی را که جای دیگری ساخته شده بارگذاری کنید.
- **Delete:** بکاپ را حذف کنید.

## گزینه‌های مهم

- **Don't touch the source (به مبدأ دست نزن):**
  - روی سرور مبدأ هیچ سرویسی متوقف نمی‌شود، هیچ چیزی تغییر نمی‌کند و هیچ دیتایی پاک نمی‌شود.
  - برای اینکه کپی سالم باشد، از Snapshot ویندوز (VSS) کپی گرفته می‌شود.
- **Restart & verify fully up (ری‌استارت و اطمینان از بالا آمدن کامل):**
  - فقط ری‌استارت کردن نیست؛ ابزار صبر می‌کند تا سرویس Core و Probe هر دو Running شوند، وب‌اینترفیس جواب بدهد و بعد از ۴۵ ثانیه هم پایدار بماند.
  - اگر سرویسی در این مدت بیفتد، خودکار دوباره استارت می‌شود.
  - اگر PRTG کامل بالا نیاید، کار با خطا تمام می‌شود.
  - همین بررسی روی سرورهای مقصد هم انجام می‌شود.
- **Copy the source license (کپی لایسنس مبدأ):**
  - اگر تیک بخورد، لایسنس مبدأ روی مقصد کپی می‌شود.
  - اگر تیک نخورد، مقصد لایسنس خودش را نگه می‌دارد.
- **RDP در صفحهٔ Servers:**
  - پورت RDP برای هر سرور جدا تعریف می‌شود. پیش‌فرض 3389 است و قابل ویرایش است.
  - در ستون Ports، وضعیت پورت RDP و WinRM با رنگ سبز یا قرمز نمایش داده می‌شود.
  - دکمهٔ **RDP**، ریموت دسکتاپ را از همین سیستم باز می‌کند.
- **بررسی‌های اولیه (Pre-flight):** قبل از هر تغییری، این موارد روی همهٔ سرورها چک می‌شود:
  - دسترسی WinRM
  - دسترسی ادمین
  - فضای خالی دیسک
  - نسخهٔ PRTG

  اگر یکی از این‌ها مشکل داشته باشد، به هیچ سروری دست زده نمی‌شود.
- **بررسی سلامت فایل‌ها:**
  - هش SHA-256 فایل بکاپ روی Manager و دوباره روی هر مقصد چک می‌شود.
  - هش فایل `PRTG Configuration.dat` بین مبدأ و مقصد مقایسه می‌شود.

## نکات مهم بعد از انتقال

- **لایسنس**: لایسنس PRTG فقط روی یک Core هم‌زمان مجاز است. سرور قدیمی را خاموش نگه دارید و در صورت نیاز لایسنس را روی سرور جدید دوباره فعال کنید.
- **Remote Probeها**: اگر IP سرور جدید فرق می‌کند، رکورد DNS را عوض کنید یا آدرس Core را در تنظیمات هر Probe اصلاح کنید.
- **پسوردهای ذخیره‌شدهٔ VPN** و گواهی‌های ماشین توسط ویندوز (DPAPI) محافظت می‌شوند و منتقل نمی‌شوند. یک بار روی سرور جدید یوزر و پسورد VPN را وارد کنید.
- **Rollback**:
  - دیتای قبلی مقصد با نام `<datapath>.pre-restore-<timestamp>` نگه داشته می‌شود.
  - رجیستری قبلی در `C:\PrtgMover\rollback` ذخیره می‌شود.
- **VPN تمام‌تونل**: گزینهٔ «اتصال خودکار VPN بعد از ریستور» به‌صورت پیش‌فرض خاموش است، چون VPN تمام‌تونل می‌تواند اتصال WinRM را قطع کند.

## امنیت

- پسوردها هرگز به‌صورت متن ساده ذخیره نمی‌شوند.
- داشبورد با توکن محافظت می‌شود و به‌طور پیش‌فرض فقط روی `localhost` در دسترس است.
- فایل‌های بکاپ حاوی اطلاعات حساس هستند (کانفیگ PRTG، لایسنس و کلید خصوصی SSL). از آن‌ها مثل یک گاوصندوق رمز محافظت کنید.
- پوشه‌های `backups/` و `data/` و فایل `config/servers.json` هرگز نباید در گیت کامیت شوند. در `.gitignore` قرار دارند.
